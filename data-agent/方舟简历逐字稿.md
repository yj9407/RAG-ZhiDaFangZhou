# 掌柜问数（Data-Agent）— 项目经历 & 逐字稿

---

## 一、项目经历（简历版）

**2025.03 - 2025.06 &emsp; 掌柜问数（Data-Agent）— 企业级 Text-to-SQL 智能数据问答平台**

**技术栈：** Python、FastAPI、LangChain、LangGraph、MySQL、Qdrant、Elasticsearch、jieba、bge-large-zh-v1.5、Vue 3

---

### 项目介绍

基于 LangGraph 构建的企业级 Text-to-SQL 智能数据问答平台。用户用中文自然语言提问（如"去年华东区销售额前三的省份"），系统通过 12 节点 DAG 工作流自动完成语义理解→三路并行元数据召回→SQL 生成→校验→自愈修正→执行返回。将企业查数时效从"天级"压缩到"秒级"，让不懂 SQL 的业务人员直接对话数据库。

---

### 工作内容

- **设计 12 节点 LangGraph DAG 工作流**：基于 StateGraph 实现关键词提取、三路并行召回（Qdrant 向量检索 + ES 全文检索 + MySQL 关系型检索）、信息合并去重、LLM 过滤精选、SQL 生成、EXPLAIN 校验、错误自愈修正、执行返回的完整链路，通过条件路由实现 SQL 校验失败自动纠错闭环

- **搭建混合元数据检索系统**：Qdrant 向量检索解决字段/指标语义匹配，ES 全文检索解决维度值匹配，MySQL 关系型检索解决主外键关联补全问题。搭建 SQL 校验 + LLM 二次纠错闭环，通过条件路由实现错误 SQL 自动修正。配套 Loguru + ContextVar 实现全链路日志追踪

- **自研纯 Python 内存搜索引擎**：基于 jieba 分词 + 倒排索引 + 加权打分，接口完全兼容 AsyncElasticsearch，支持精确匹配与子串模糊匹配，实现与真实 ES 的零修改替换，开发环境零外部依赖即可运行

- **SSE 流式进度推送**：后端 12 节点实时推送进度事件到前端，用户可观察 AI 每一步推理过程，全流程可视化

- **元数据知识库一键构建**：从 YAML 配置文件到 MySQL + Qdrant + ES 的 6 步全自动构建脚本，新增业务表/指标的数据接入从 2 小时缩短至 10 分钟

---

### 具体成果

- 实现自然语言→SQL→数据结果的端到端自动化，业务人员无需 SQL 知识即可直接查数，查数时效从 2-3 天缩短至 10 秒级
- 三路并行召回将元数据检索时间压缩至单路约 1/3，SQL 自愈闭环使一次校验通过率达 80%+，有效抑制 LLM 幻觉
- 自研搜索引擎替代 Elasticsearch，开发环境搭建从 30 分钟缩短至 5 分钟，零外部依赖即可完整运行
- 全链路 request_id 追踪体系使线上问题定位效率提升 3-5 倍

**"12 节点 DAG 工作流。"**

📁 `app/agent/graph.py:33-44` — 12 个 `add_node()` 调用：
```
extract_keywords → 关键词提取
recall_column   → 字段向量召回
recall_value    → 维度值全文召回
recall_metric   → 指标向量召回
merge_retrieved_info → 合并去重+补主外键
filter_metric   → LLM 过滤指标
filter_table    → LLM 过滤表与字段
add_extra_context → 补充日期/DB版本
generate_sql    → LLM 生成 SQL
validate_sql    → EXPLAIN 语法校验
correct_sql     → LLM 纠错修正
execute_sql     → 执行返回结果
```

> 12 个节点分布在 `app/agent/nodes/` 目录下 12 个文件，每个文件一个节点。

**"SQL 校验失败自动纠错闭环。"**

📁 `app/agent/graph.py:61-65` — 条件路由：
```python
graph_builder.add_conditional_edges("validate_sql",
    lambda state: "execute_sql" if state["error"] is None else "correct_sql",
    {"execute_sql": "execute_sql", "correct_sql": "correct_sql"})
graph_builder.add_edge("correct_sql", "execute_sql")
```

> error 为 None 就走执行，有错误就走纠正，纠正完再执行。
